# Testing Rules

## 测试范围

- Schema：合法输入、缺失字段、别名、边界值和非法输入。
- Service：主流程、分支、权限、幂等、事务失败和外部依赖异常。
- API：状态码、响应结构、鉴权和错误映射。
- DAO/Client：使用集成测试或契约测试验证协议，不把真实生产依赖带入单元测试。
- Bug 修复：必须增加能在修复前失败、修复后通过的回归测试。

## 编写规范

- 测试名称清晰表达场景和期望结果。
- 一个测试聚焦一个行为，使用 Arrange、Act、Assert 组织结构。
- 测试数据由 fixture 或 builder 创建，避免依赖执行顺序和共享可变状态。
- 时间、随机数、网络、配置和文件系统依赖应可注入或 mock。
- Mock 外部边界，不要 Mock 被测业务逻辑本身。
- 异步代码使用与项目测试栈匹配的异步测试方式。

## 验证层级

```bash
# 先运行与改动直接相关的测试
python -m pytest path/to/test_file.py -q

# 再运行项目测试
make test

# 最后执行统一质量门禁
make check
```

测试因环境依赖无法运行时，交付说明必须列出缺失条件、已完成的替代验证和剩余风险。
