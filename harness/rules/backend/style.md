# Python Style Rules

## Black

- Python 文件统一使用 Black 格式化。
- 默认行宽为 88。
- Black 是唯一的代码排版标准，不手工维护与 Black 冲突的格式。
- 模板不固定 `target-version`；语法版本必须服从目标项目实际声明的运行时。
- 业务变更不得附带无关文件的全量格式化。

标准命令：

```bash
make format
make format-check
```

## 命名与结构

- 模块、函数和变量使用 `snake_case`。
- 类和异常使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。
- 名称应表达业务含义，避免 `data1`、`tmp_obj`、`do_process` 等模糊命名。
- 函数保持单一职责；复杂条件拆成有业务含义的辅助函数。
- 公共函数、Service 方法和复杂返回值应提供类型标注。
- 不使用 `from module import *`，避免修改 `sys.path` 作为正式依赖方案。

## 导入

导入按以下三组组织，组间空一行：

1. Python 标准库。
2. 第三方库。
3. 当前项目模块。

删除未使用导入。避免仅为绕开循环依赖而把导入移动到函数体内。

## 注释与文档

- 注释解释“为什么”和约束条件，不复述代码本身。
- 对外接口、复杂业务规则和不直观算法应提供简洁 docstring。
- TODO 必须包含可执行事项；有任务系统时附任务编号。
- 代码、注释和日志使用项目既有语言风格，同一模块内保持一致。

## 异常与日志

- 禁止裸 `except:`，禁止捕获异常后静默忽略。
- 捕获宽泛异常必须记录上下文，随后转换为明确错误或重新抛出。
- 使用项目统一 logger，不使用 `print` 输出运行日志。
- 日志应带必要业务标识，但不得泄露敏感数据。
