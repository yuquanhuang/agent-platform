# Cross-stack Contract Rules

## 单一来源

- API 优先使用 OpenAPI，事件和共享对象使用 JSON Schema、AsyncAPI 或项目声明的等价规范。
- 前端 API Client 和类型应从契约生成或由一个明确的共享包提供。
- 禁止前后端分别维护含义相同但可能漂移的手写 DTO。

## 兼容性

- 新增字段优先保持可选和向后兼容；删除、重命名和语义变化必须提供迁移窗口。
- 明确日期时区、金额精度、分页、空值、枚举、错误结构和文件上传约定。
- SSE、WebSocket 和消息事件必须定义事件名、顺序、重连、幂等和结束语义。

## 变更流程

1. 先修改或确认契约。
2. 校验契约格式和兼容性。
3. 更新生成代码或共享类型。
4. 实现生产者和消费者。
5. 运行后端契约测试、前端 typecheck 和必要的集成/E2E 测试。

生成文件是否提交到 Git 必须由项目统一决定，禁止同一仓库内混用两种策略。
